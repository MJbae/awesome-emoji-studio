# 5개 언어 지원과 자연스러움 검토

## 언어 선택 규칙

지원 언어는 **영어(en), 한국어(ko), 일본어(ja), 중국어 간체(zh-CN), 중국어 번체(zh-TW)**입니다. 태국어는 UI 리소스·생성 대상·메타데이터 선택에서 제외했습니다.

사용자가 승인한 권장안에 따라 IP 위치 대신 브라우저·기기의 선호 언어를 사용합니다. 접속 국가와 기기 언어는 다를 수 있습니다. 위치 조회 서비스나 추가 네트워크 요청은 사용하지 않습니다.

1. 이전에 직접 선택한 지원 언어가 있으면 우선합니다 (`localStorage.i18nextLng`).
2. 없으면 `navigator.languages`에서 지원하는 첫 언어를 사용합니다.
3. 지원 언어가 없거나 감지할 수 없으면 영어를 사용합니다.

| 선호 언어 예시 | 적용 언어 |
| --- | --- |
| `en-US`, `en-GB`, `en-AU` | 영어 |
| `ko-KR` | 한국어 |
| `ja-JP` | 일본어 |
| `zh`, `zh-CN`, `zh-SG`, `zh-Hans` | 중국어 간체 |
| `zh-TW`, `zh-HK`, `zh-MO`, `zh-Hant` | 중국어 번체 |
| `zh-Hant-CN`, `zh-Hans-TW` | 지역보다 명시된 문자 체계를 우선: 각각 번체·간체 |
| `fr-FR`, `de-DE`, `th-TH`만 있는 경우 | 영어 |

저장된 태국어·잘못된 언어 코드는 무시하고 기기 언어로 다시 판단합니다. 언어 설정 저장이 제한되어도 직접 선택한 언어는 현재 세션에 유지되며, 이후 기기 언어 변경 이벤트로 덮어쓰지 않습니다. 브라우저의 언어 변경 이벤트는 직접 저장한 선택이 없을 때 자동 반영합니다.

## UI와 생성 언어

- 헤더와 API 키 설정 창에서 언어를 변경할 수 있습니다. API 키가 없어도 선택 가능합니다.
- 문서의 `html.lang`, 버튼·설명·오류·화면 읽기 도구용 이름, 이미지 설명, 전문가·플랫폼 이름이 함께 바뀝니다.
- 언어 전환을 위해 페이지를 새로고침하지 않습니다. 작성 중인 컨셉, 참고 이미지, 생성 대상 언어, 단계와 산출물은 유지합니다.
- 새 작업의 생성 대상은 감지된 인터페이스 언어를 기본값으로 사용합니다. 사용자가 고른 생성 대상은 UI 언어 전환과 독립적으로 유지됩니다.
- 메타데이터는 5개 언어 중 선택할 수 있습니다. 생성 프롬프트는 선택한 언어의 자연스러운 문체와 중국어 문자 체계를 명시합니다. 기술적인 `imagePrompt`, JSON 키·열거값은 계약대로 유지합니다.

## 도입 전 에이전트 검토

구현 담당과 별도로 지정한 언어 검토 에이전트가 전체 정적 문구를 검토하고 PASS 판정을 낸 후보만 도입했습니다. 일반 설명, 동작 버튼, 오류, 접근성 문구, 복수형, 보간 변수, 플랫폼 설명을 모두 포함합니다. 완료 상태에 실패한 생성도 포함된다는 점을 확인하여 ‘완성’ 대신 중립적인 ‘생성 결과’ 제목으로 재검토했습니다.

| 언어 | 담당 검토 에이전트 | 검토 범위 | 판정 |
| --- | --- | --- | --- |
| 영어·한국어 | `review_en_ko` | 계약 문구 254개, 영어 복수형 12개 추가 | PASS |
| 일본어 | `review_ja` | 계약 문구 254개, 모바일 짧은 단계명 별도 검토 | PASS |
| 중국어 간체·번체 | `review_zh` | 각 254개, 본토·대만 어휘와 표기를 별도 검토 | PASS |

[영어·한국어 보고서](en-ko-review.md) · [일본어 보고서](ja-review.md) · [중국어 보고서](zh-review.md) · [생성 문체 지침 검토](generated-language-review.md)

이는 AI 에이전트 검토입니다. 원어민 인간 감수나 실제 Gemini 응답의 품질 인증을 뜻하지 않습니다. 런타임 생성 프롬프트의 자기 검토 지침과 정적 번역의 별도 에이전트 검수도 구분합니다.

## 검토 없이 문구가 들어가지 않도록 하는 절차

`npm run check:i18n`은 다음을 확인합니다.

- 배포 리소스가 정확히 5개 언어인지
- 계약 키 누락·빈 문구·보간 변수 불일치가 없는지
- 각 문구가 에이전트 승인본의 해시와 일치하는지
- 해당 검토 보고서가 있는지
- 생성 문체 지침이 별도 에이전트 검토를 받은 소스와 일치하는지

`review-manifest.json`의 해시는 키 순서를 정렬한 canonical JSON의 SHA-256입니다. 공백·정렬 같은 파일 포맷 변경은 문구 변경으로 간주하지 않습니다. 보고서의 원본 파일 해시와 표현 방식이 다를 수 있습니다. 생성 문체 지침 소스는 별도로 CRLF를 LF로 정규화한 SHA-256을 사용하므로 Windows 체크아웃도 검토 승인을 유지합니다.

웹·Electron 빌드와 데스크톱 패키징은 이 검사를 먼저 실행합니다. 문구를 바꾸려면 언어 담당 에이전트가 다시 전체 영향 범위를 검토하고, 승인 후보·보고서·해시를 함께 갱신해야 합니다. 검사는 검토 승인과 파일의 연결을 확인하며, 언어의 자연스러움을 코드만으로 판정하지 않습니다.
